# 最終課題 設計書 — Genesis 上の Go2 による LiDAR 巡回と障害物回避

作成: 2026-10-20 / 締切: 2026-11-02(月)10:00 / 環境: M1 Max 32GB(macOS ネイティブ, Metal), genesis-world 1.4.4

## 1. タスク定義(1 文)

**強化学習で獲得した歩行方策の上に、疑似 LiDAR を使った巡回・障害物回避のナビゲーション層を載せ、障害物配置をランダム化した複数シーンで巡回成功率を定量評価する。**

## 2. なぜこの構成か(レポートの「目的」)

- 実機 Go2 の自律巡回は「LiDAR SLAM/自己位置推定 → 経路計画 → 速度指令 → 歩行コントローラ」の層構造。本課題はその **下 2 層(速度指令 → 歩行)を RL で、上の層を古典的ナビゲーションで** 構成し、シミュレータ上で同じ構造を再現する
- 歩行方策は「与えられた速度指令に追従する」ことだけを学ぶ(タスク非依存)。巡回・回避はその上で差し替え可能 → 第4回で学んだ ROS 2 の疎結合設計と同じ考え方
- 評価は「1 回動いた動画」ではなく、**配置をランダム化した N シーンでの成功率・衝突率・所要時間**(基礎編最終課題と同じ流儀)

## 3. システム構成

```
                 ┌──────────────────────────────────────────────┐
                 │  ナビゲーション層(自作、古典制御)            │
 ウェイポイント ─►│  経路追従(P 制御) + 障害物回避(疑似 LiDAR   │──► 速度指令 (vx, vy, ωz)
                 │  → セクタ最小距離 → 反発ベクトル / VFH 風)  │
                 └──────────────────────────────────────────────┘
                                   ▲ 距離配列(360°)                   │
                 ┌─────────────────┴────────────┐                     ▼
                 │ Genesis Raycaster(SphericalPattern) │   ┌──────────────────────┐
                 │ Go2 胴体リンクに取付、max_range 5 m  │   │ 歩行方策(RL, PPO)    │
                 └──────────────────────────────┘   │ 45 次元 obs → 12 関節  │
                                                     └──────────────────────┘
                                                                │ 目標関節角 → PD
                                                                ▼
                                              Genesis 物理(Go2 + 床 + 障害物 Box/Cylinder)
```

### 3.1 歩行方策(RL)— 段階 5
- `go2_train_patrol.py`: 指令範囲 vx [0, 0.8] / vy [-0.2, 0.2] / ωz [-0.8, 0.8]、4096 env × 300 it(M1 Max で約 10 分)
- 評価指標: `rew_tracking_lin_vel`, `rew_tracking_ang_vel`、転倒率
- 比較(ablation 候補): 指令範囲を広げた方策 vs 既定方策(前進のみ)で巡回成功率がどう変わるか → 「なぜ再学習が必要か」の根拠

### 3.2 疑似 LiDAR
- `scene.add_sensor(gs.options.sensors.Raycaster(pattern=SphericalPattern(fov=(360, 0), n_points=(72, 1)), entity_idx=robot, pos_offset=(0,0,0.15), max_range=5.0, return_points=False))` を `scene.build()` 前に追加(go2_env.py にカメラと同様の差し込み口を足す)
- 72 本(5° 刻み)の水平スキャン。実機 Go2 の LiDAR(3D)に対し「2D スキャンに落とした」と明記
- **未検証**: Metal での Raycaster 動作と per-step コスト。段階 5 の直後に単体テスト

### 3.3 ナビゲーション層(自作)
- 経路追従: `go2_patrol.py` の `WaypointFollower`(P 制御)を流用
- 障害物回避: LiDAR 距離をセクタ(例 12 セクタ)に集約 → 進行方向セクタの最小距離が閾値未満なら、空いている方向へ ωz を加える(反発ベクトル法 / VFH の簡易版)。**学習不要・決定的・説明可能**
- 停止条件: 前方 0.4 m 未満で vx=0(安全停止)。これも実機の安全設計に対応

### 3.4 シーン
- 床 + 障害物(`gs.morphs.Box` / `Cylinder`、fixed=True)を **乱数で配置**(個数 3〜6、ウェイポイント上には置かない)
- 巡回経路: 4 隅の正方形(2 m 角)または 8 点の円。1 周 = 成功

## 4. 評価設計

| 指標 | 定義 |
|---|---|
| 巡回成功率 | 制限時間(60 s)内に全ウェイポイント到達 かつ 転倒なし |
| 衝突率 | LiDAR 最小距離 < 0.25 m(胴体半径相当)となったステップが 1 つでもあれば衝突 |
| 所要時間 | 成功エピソードの平均 |
| 経路効率 | 実走行距離 / ウェイポイント間直線距離の合計 |

- シーン: 乱数 seed 0〜19 の **20 配置**(障害物なし 5 + あり 15)
- 条件比較(2×2 を基本形に):
  - 歩行方策: 既定(前進のみ)/ 指令範囲拡張
  - 回避: なし / あり
- 期待する結論: 「回避なし」は障害物ありで衝突率が跳ね上がる、「既定方策」は旋回できず成功率が低い → 両方必要、を数字で示す
- 20 配置 × 4 条件 = 80 エピソード × 約 40 s = M1 で録画なしなら 1 時間弱(録画は代表例のみ)

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| Raycaster が Metal で動かない/遅い | 障害物位置は既知なので、幾何計算の「仮想 LiDAR」で代替(レポートに明記) |
| 拡張指令で方策が旋回に追従しない | イテレーション 300 → 600、`tracking_sigma` 調整、ωz 範囲を ±0.5 に縮小 |
| 回避中に転倒 | ωz の変化率制限(action_rate の思想をナビ層にも)、障害物間隔を 1.2 m 以上に |
| 録画の長さ・容量 | 代表 3 本のみ 1280×720、残りは録画なしで評価 |
