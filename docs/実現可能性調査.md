# Genesis × Go2 歩行 — M1 Mac ネイティブでの実現可能性調査(半日)

目的: 最終課題 C 案(Genesis で Go2 を歩かせて巡回させる)が **自分の M1 Mac + Colab だけで成立するか** を半日で判定する。
判定基準は「段階 3(headless 録画)まで通るか」。学習の質はここでは見ない。

作成日: 2026-10-20 / 対象バージョン: **genesis-world 1.4.4**(PyPI 最新)、rsl-rl-lib 5.5.1、Python 3.10〜3.13

## 結果(2026-10-20, M1 Max 32GB, macOS ネイティブ conda 環境 `py311_genesis`)

**全段階クリア。M1 Max だけで完結し、Colab / DGX は不要。**

| 段階 | 結果 |
|---|---|
| 1 インストール | genesis-world 1.4.4 / rsl-rl-lib 5.5.1 / torch 2.14.1。`gs.init(backend=gs.gpu)` → `gs.metal`, device `mps` |
| 2 短縮学習(256 env × 10 it) | Iteration time 0.65 s(初回 6.7 s は JIT)、約 9,300 steps/s、合計 12 秒 |
| 3 headless 録画 | 640×360: 18 steps/s(JIT 込み)、1280×720: 39 steps/s。Go2 が正しく描画、追従カメラ動作 |
| 4 本番学習(4096 env × 101 it) | **3 分 51 秒**(JIT 約 1 分 + 学習 2 分 36 秒)、67,287 steps/s、`rew_tracking_lin_vel` 0.9135、episode length 1001(転倒ゼロ)。録画で歩行を確認 |

参考: RTX 3070 Ti(CUDA)は同条件 51 秒 → M1 Max の Metal は約 3 倍遅い程度。比較実験を多数回す段階になっても M1 で十分回る。

無害な警告: `QuadrantsWarning: Assign may lose precision`、`GLD_TEXTURE_INDEX_CUBE_MAP is unloadable`、`qpos0 exceeds joint limits`。

環境: `conda create -n py311_genesis python=3.11` → `pip install torch "genesis-world==1.4.4" "rsl-rl-lib>=5.0.0" tensorboard`。作業場所 `最終課題/work/genesis-world/examples/locomotion/`(v1.4.4 tag の clone に自作 4 本を上書き)。

## 0. 事前にコンテナ(CPU, Linux)で確認済みのこと

| 確認項目 | 結果 |
|---|---|
| `pip install genesis-world==1.4.4 "rsl-rl-lib>=5.0.0"` | 通る(torch は別途) |
| `go2_train.py -b 8 --max-iterations 3`(CPU) | 走る。2 分 45 秒(ほぼ JIT コンパイル。学習自体は 1 イテレーション 0.2 秒)。`logs/<exp>/cfgs.pkl` と `model_<最終it>.pt` が保存される |
| `go2_record.py`(Viewer なし + カメラ録画) | **通る**。8 秒・400 フレーム・640×360 の mp4 が生成され、Go2 が描画されている(`smoke.mp4`, `frame_*.png`) |
| 録画 API(v1.4.4 実装) | `cam.start_recording(save_to_filename=..., fps=...)` → `scene.step()` ごとに自動描画・エンコード → `cam.stop_recording()`(引数なし)。**docs「latest」に載っている `stop_recording(save_to_filename=...)` は旧 API で、1.4.4 では TypeError** |
| 既定の学習の指令範囲 | `command_cfg = {vx: [0.5, 0.5], vy: [0, 0], yaw: [0, 0]}` — **前進 0.5 m/s しか学ばない**(下記 §4) |

→ Linux CPU で通ったので、M1 で残るリスクは「Metal バックエンド固有の問題」と「速度」だけ。

## 2. 段階と go/no-go

| 段階 | コマンド | 見るもの | 目安 | 撤退条件 |
|---|---|---|---|---|
| 1 インストール | 上記 | import が通る、`gs.backend` が metal | 30 分 | pip が通らない / Metal が選べない(→ `gs.cpu` で続行可だが速度不利) |
| 2 短縮学習 | `python go2_train.py -b 256 --max-iterations 10 -e smoke` | 落ちずに 10 イテレーション完走、`logs/smoke/model_9.pt` 生成。**1 イテレーションの秒数を記録** | 30 分 | Metal 固有のエラーが 2 回の対処で消えない |
| 3 録画 | `python go2_record.py -e smoke --ckpt 9 --out smoke.mp4 --res 640 360 --follow` | `smoke.mp4` が出て Go2 が映る(歩けていなくてよい)。**steps/s を記録** | 1 時間 | 録画が出ない / 1 フレーム数秒以上 → `--backend cpu` で再試行、それでも駄目なら撤退 |
| 4 本番学習の所要時間 | `python go2_train.py -b 1024 --max-iterations 101 -e go2-walking` | 完走時間。歩くか(`go2_record.py -e go2-walking --ckpt 100`) | 30 分〜 | **1 時間超なら学習だけ Colab(T4)へ**(`genesis_go2_colab.ipynb`)。`.pt` は `torch.load(..., map_location="mps")` で持ち込める |
| 5 巡回(最終課題の本体) | `python go2_train_patrol.py -e go2-patrol -b 1024 --max-iterations 300` → `python go2_patrol.py -e go2-patrol --ckpt 299 --waypoints square` | 旋回指令に追従して 4 隅を回れるか。`go2_patrol_log.csv` で軌跡を確認 | 学習 30 分〜数時間(M1 なら Colab 推奨) | 追従できない → 指令範囲・報酬・イテレーション数の調整(ここからは「調査」ではなく「開発」) |

段階 3 が通れば C 案の最大リスク(動画が作れない)は消える。段階 4 は「M1 で完結するか、Colab と分業か」の判断材料。

Colab を使う場合: `genesis_go2_colab.ipynb` を Colab で開き(ランタイム = GPU)、このフォルダの `.py` 4 本を Drive の `MyDrive/genesis_go2_feasibility/` に置いてから上から実行。§3 で smoke 録画、§4 で既定例題、§5 で巡回用学習+巡回録画+軌跡プロット、§6 で Drive に書き戻し。Colab 上の headless 描画は `PYOPENGL_PLATFORM=egl` で行う(ノートブック内で設定済み。**未検証**: Colab の EGL で Genesis のラスタライザが動くかは実行して確認)。

## 3. M1 で起こりうる問題と対処

| 症状 | 対処 |
|---|---|
| Viewer を開くと落ちる / スレッドのエラー | 本調査では Viewer を使わない(`show_viewer=False` + カメラ録画)。見たいときだけ `go2_eval.py` を別途 |
| `cv2.imshow` 関連のエラー | カメラは `GUI=False` のまま(go2_record.py は既定で False) |
| 4096 環境でメモリ不足 / 極端に遅い | `-b 256 → 512 → 1024` と上げる。`--max-iterations` は 101 のまま |
| `rsl-rl-lib` の ImportError | 5 系が必要。講座サンプル記事の `rsl_rl v1.0.2` は旧版なので入れない |
| `rendered_envs_idx` エラー(Qiita 記事の追記) | 1.4.4 の例題は `rendered_envs_idx=[0]` で正しい。記事の `n_rendered_envs` は旧 API |
| 学習が走るが報酬が上がらない | 段階 2 では見ない。段階 4 で 101 イテレーション後に `rew_tracking_lin_vel` が上昇していれば OK |

## 4. 重要な発見: 既定の例題は「前進 0.5 m/s」しか学ばない

v1.4.4 の `go2_train.py` の `command_cfg` は vx = [0.5, 0.5]、vy = [0, 0]、yaw = [0, 0] に固定。
つまり **旋回・停止・速度変化は学習していない**ので、巡回(ウェイポイント追従)をさせるには

1. `command_cfg` を例えば vx [-0.5, 1.0]、vy [-0.3, 0.3]、yaw [-1.0, 1.0] に広げて再学習(学習時間は増える)
2. `go2_record.py` の `SCRIPT` を「前進 → 旋回 → 前進 → 停止」に書き換えて追従を確認
3. 追従できたら、ウェイポイント列から (vx, yaw) を計算する簡単な追従則を足す

これは実現可能性調査の次の段階(段階 5)であり、同時に **最終課題の「創造性・技術力」の中身そのもの**(指令範囲の設計、再学習、追従性能の比較)になる。

段階 5 用に同梱したもの:
- `go2_train_patrol.py`: `go2_train.py` の設定関数を流用し、`command_cfg` だけを vx [0, 0.8] / vy [-0.2, 0.2] / yaw [-0.8, 0.8] に上書きして学習(既定 300 イテレーション)
- `go2_patrol.py`: ウェイポイント列(line / square / circle)を P 制御で追従 → 速度指令 → 学習済み方策、を headless 録画。`<out>_log.csv` に t, x, y, yaw, cmd_vx, cmd_yaw を保存(レポートの軌跡図に使う)。CPU で経路が通ることは確認済み(`patrol_smoke.mp4`。方策は 3 イテレーションなので歩けていない)
- 実機 Go2 の「Nav2 → cmd_vel → 歩行コントローラ」と同じ層構造にしてあるので、レポートで実機との対応を論じやすい
