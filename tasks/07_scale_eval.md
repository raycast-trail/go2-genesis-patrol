# T07: 評価の拡大(50 配置)と再現性の切り分け

## 目的
1. 15 配置では v1 と v2 の差を検定で示せなかった(McNemar p = 1.0)。障害物あり配置を **45 配置(seed 5〜49)** に増やし、v1 回避なし / v1 回避あり / v2 回避あり の 3 条件を比較して、信頼区間を狭める。既定方策は 15 配置の結果で十分(全条件 0%)なので増やさない
2. T05 で見つかった「単発実行(録画あり)とバッチ実行(録画なし)で結果が変わる」現象を切り分ける。バッチ同士は再現するので、**録画の有無(カメラの有無)が物理に影響している**可能性が高い。これが事実なら、動画の実行と評価の実行は同じ条件にしなければならない

## 手順
1. **再現性の切り分け**(先にやる。15 分):
   - seed 12、拡張方策、v2 回避ありで、次の 4 条件を各 3 回実行し、到達数・所要時間・接触を表にする
     - (a) `--no-video`(バッチと同じ)
     - (b) 録画あり(`--out /tmp/x.mp4`、俯瞰)
     - (c) 録画あり + `--mcap`
     - (d) `--no-video` だが `camera_cfg` だけ渡す(カメラは作るが録画しない)— `go2_patrol.py` に `--camera-only` のような隠し引数を足してよい
   - 同一条件の 3 回が一致し、条件間で違うなら「カメラの有無が物理に影響」。同一条件でもばらつくなら「真の非決定性」。どちらかを報告で断定し、根拠の表を付ける
   - カメラの有無が原因なら: **評価と録画で物理が同じになる方法**を 1 つ試す(例: 評価でもカメラを作って録画だけしない)。効果があれば T04/T05 の結果とどう整合するかを書く(再評価はしない。T07 の 45 配置はこの知見を反映した条件で回す)
2. シーン生成: `eval/scenes.py` で seed 20〜49 を追加生成(既存 0〜19 は変更しない)
3. 評価: `eval/run_eval.py` で seed 5〜49(45 配置)× {v1 回避なし, v1 回避あり, v2 回避あり}、拡張方策のみ。`results/eval_50/episodes.csv`(135 本、約 25 分)。segfault 対策の再開機能はそのまま使う
4. `eval/summarize.py` に `--scenes 5-49` と 3 条件の比較を追加:
   - 成功率・接触率・ニアミス率・成功分の平均所要・経路効率、各 Wilson 95% CI
   - 対応あり McNemar: (v1 なし vs v1 あり)、(v1 あり vs v2 あり) の成功と接触
   - 所要時間: v1 あり vs v2 あり の対応あり比較(両方成功した配置のみ、差の中央値と Wilcoxon 符号順位検定は `math` だけで実装が面倒なら差の分布のヒストグラムで代替してよい)
   - `results/eval_50/summary.md`, `summary.png`(成功率・接触率・所要時間の 3 枚)
5. 失敗配置の一覧(seed、条件、終了理由、到達数)と、v1 で失敗し v2 で成功した配置・その逆の配置を列挙

## 受け入れ条件
- [ ] 再現性の切り分け表(4 条件 × 3 回)と結論
- [ ] `results/eval_50/episodes.csv` が 135 本揃う(欠損なし)
- [ ] `summary.md` に 3 条件の表・CI・McNemar・所要時間比較
- [ ] `reports/07_scale_eval.md`: 結果、15 配置の結論と変わった点・変わらなかった点、失敗配置の分析、v1/v2 のトレードオフの言語化(速度 vs 確実性 vs 経路効率)
