# T12: 3D 疑似 LiDAR と「高さ方向で通行可否が変わる障害物」— 期限 10/26、未完なら切り捨て

## 目的
2D スキャン(センサ高さの水平面)では見えない障害物で、実機と同じ失敗を再現し、3D 化で直す。
- **低い障害物**(高さ 0.15 m の箱): スキャン面より下 → 2D では見えずに踏む・接触する
- **ひさし(テーブル)**: 細い脚の上に天板。2D は脚しか見えず「通れる」と判断し、胴体が天板に当たる
- (余力)**崖**: 床の落差。2D では床の有無が分からない

3D パターンで点群を取り、**胴体の高さ帯に入る点だけを 72 本の仮想 2D スキャンに投影**して、v1(下層)と v3(地図 + A*)にそのまま渡す。実機の voxel layer / STVL と同じ処理で、**ナビ層・歩行方策は変えない**。これは余力タスクで、10/26 中に受け入れ条件を満たせなければその時点の結果と考察を `reports/12` に書いて止める。T11 までの提出物は確定しているので、v1/v2/v3 の既存の結果・動画・スクリプトの挙動を変えないこと(新機能はすべてオプション引数で有効化)。

## 手順

### 1. 幾何の計測(最初にやる。30 分)
立位の Go2 で次を実測し、報告に表で書く: base リンク原点の z、センサの z(= base z + 0.15)、胴体の最高点 z(`robot.get_AABB()` か各リンクの AABB の max z。脚・頭を含む)、遊脚の最大高さ(T01 の台本歩行 1 周分の足先 z の最大)。
これに基づき寸法を決める(目安。実測で矛盾したら調整し、理由を書く):
- 低い箱: 高さ **0.15 m**(センサ面より十分下、遊脚高さより上 → 踏むと転倒か接触)。幅 0.3〜0.5 m
- テーブル: 天板の **下面 = 胴体最高点 − 0.03 m**、厚さ 0.04 m、**上面がセンサ z − 0.03 m より低い**こと(2D で見えない条件)。天板 0.6〜0.9 m 角、脚は半径 0.02 m の円柱 4 本(2D には脚だけ見える)。この条件が成り立たない(胴体最高点とセンサが近すぎる)場合は、T12 の実験に限り 2D・3D 両方のセンサ取付高さを `pos_offset` 0.20 m にして成立させ、報告に明記する(既定の 0.15 m は変えない)
- 崖(余力): 床面を高さ 0.3 m の台(8 × 8 m を 4 つの箱で構成し、1 × 1 m の穴を 1 つ残す)にする。穴に落ちたら失敗

### 2. 3D パターン(`nav/lidar.py`)
- `make_lidar_cfg(mode="3d")`: `SphericalPattern(fov=(360, 60), n_points=(72, 16))`(垂直 −30°〜+30°、4° 刻み。**fov の中心が水平かどうかは立位で点の z を出して確認**し、報告に書く)。`return_points=True, return_world_frame=True` は同じ
- `read_scan_3d(env) -> (scan2d, pts_band, pts_all, raw)`: 点群 (72×16, 3) を次で分類
  - **地面**: z < 床面 + 0.05(台の上なら台の上面基準)→ 空き(レイ上を空きにするために距離は残す)
  - **胴体帯**: 床面 + 0.05 ≤ z ≤ 胴体最高点 + 0.10 → 障害物
  - **頭上**: それより上 → 無視(障害物にしない)
  - **崖(余力)**: 下向きレイが期待床面より 0.10 m 以上低い所に当たった → レイが床面を横切る (x, y) を障害物
  - `scan2d[k]` = 方位 k の 16 層のうち障害物に分類された点の **最小水平距離**(無ければ max_range)。これを既存の `sector_min` / `ObstacleAvoider` / `GridMap.update` にそのまま渡す(`pts_world` には胴体帯の点を渡す。`GridMap.update` のレイ上の空き更新は投影後の 72 本で行う)
- per-step コストを 2D(72 本)と 3D(1,152 本)で計測(立位 200 ステップ、CPU バックエンド)。3D が 2D + 5 ms/step を超えるなら層数を 8(7.5° 刻み)に落とし、どちらを採ったか報告に書く
- 単体テスト `eval/lidar3d_test.py`: 既知配置(正面 1.3 m に低い箱、右 1.5 m にテーブル、左 1.5 m に従来の高い箱)で立位 100 ステップ → 2D スキャンと 3D 投影スキャンを極座標で並べて描画 `results/t12_lidar3d_test.png`。**2D では低い箱とテーブル天板が見えず脚だけ見える、3D では 3 つとも見える**ことを図で示す。点群の高さ分類を色分けした 3D 散布図も 1 枚

### 3. シーン生成(`eval/scenes.py`)
- 障害物タイプを追加: `lowbox`(size [w, w, 0.15])、`table`(top_size, top_z_bottom, thickness, leg_radius=0.02)。`spec_to_morphs` で天板 Box + 脚 Cylinder 4 本(すべて fixed)。`_radius` はテーブルなら天板の半径
- `--profile mixed` で **seed 100〜129 の 30 配置**を生成し `results/scenes/seed_1NN.json` に保存: 各配置に 高い障害物 1〜2、低い箱 1〜2、テーブル 1(経路との交差条件は既存と同じ: ウェイポイント 0.5 m、初期位置 1.0 m、表面間 1.2 m)。**経路上(表面クリアランス < 0.2 m)に低い箱かテーブルが少なくとも 1 つ**来るよう棄却サンプリングする(そうでないと 2D でも成功してしまい差が出ない)
- 既存 seed 0〜49 は変更しない

### 4. 巡回と評価
- `go2_patrol.py` に `--lidar 2d|3d`(既定 2d)。3D のとき `read_scan_3d` を使う。接触判定はテーブルの天板・脚・低い箱も含める(`env.obstacles` に全部入るので既存の `get_contacts` ループで足りるはず。確認する)。転倒(`fell`)も記録
- `eval/run_eval.py` に `--lidar` を追加。**30 配置 × {v3 + 2D, v3 + 3D}** を `results/eval_3d/episodes.csv` に(約 10 分)。`summarize.py` に 2 条件比較を追加: 成功率・接触率・転倒率・所要・経路効率、Wilson CI、対応あり McNemar(成功・接触)、所要時間の符号検定。**失敗の内訳を障害物タイプ別に**(低い箱に接触 / テーブルに接触 / 転倒 / 時間切れ)
- 代表配置 2 つ(テーブルが経路上にあるもの、低い箱が経路上にあるもの)で 2D・3D 各 1 本録画(俯瞰寄せ `--camera overhead-close`、`--mcap`)。軌跡図に障害物を種類別に描く(低い箱 = 薄い灰、テーブル = 輪郭のみ)
- 期待する結果: 2D は接触・転倒が多く、3D は接触 0%。3D でも失敗が出る場合はログから原因を書く(例: 低い箱が近すぎて停止距離 0.45 m で間に合わない → 調整候補 1)

### 5. MCAP(提出後の SLAM 実験の素材)
`--mcap` 時に 3D 条件では追加で記録:
- `/lidar/points3d`: 全点群(PointCloud、高さ分類をフィールドに)
- `/imu`: 胴体の角速度(観測にある)、線加速度(`get_vel` の差分 / dt、重力を加える)、`foxglove.messages` に IMU スキーマが無ければ JSON チャンネルでよい
- 既存の `/scan`, `/map`, `/plan`, TF はそのまま。Foxglove で開けることは人間が確認する

### 6. (余力、手順 1〜5 が 10/24 までに終わった場合のみ)崖
手順 1 の台 + 穴で seed 200〜209 の 10 配置(穴が経路上に来るようにする)。2D は落ちる、3D は避ける、を 10 配置で示す。台の上面を床面としてセンサの地面判定・胴体帯の基準を台の高さ分ずらすこと。`base_init_pos` の z も +0.3

## 調整候補(最大 2 つ)
1. 3D でも低い箱に接触する場合: 低い箱に対する停止距離を v1 の 0.45 → 0.60 m に(3D 条件のみ。`ObstacleAvoider` の引数で渡す)
2. テーブルの脚で 2D が止まってしまい差が出ない場合: 脚の半径を 0.02 → 0.015 m、脚を天板の中央寄りに(2D の回廊判定に入りにくくする)。それでも駄目なら天板 1 辺を 1.0 m に
